# 异步与错误处理

本文件用于异步流程、并发、错误传播和状态清理。具体库与项目请求链路以宿主项目为准；个人工具生态中的 `@mixte/use` 是优先检查的现成能力。

## async / await

- 普通异步流程默认使用 `async` / `await`，让顺序关系直接可见。
- 短后处理链可以使用 `.then()` / `.finally()`；不要为了“全都 await”机械改写已有自然链式代码。
- 脚本型入口可以使用 async IIFE，保持入口逻辑集中。

## 顺序与并发

先判断业务要求：

| 需求 | 选择 |
| --- | --- |
| 后一个依赖前一个 | 顺序 `await` |
| 一批任务互不依赖，需要全部成功 | `Promise.all` |
| 一批任务全部完成，但允许部分失败 | `Promise.allSettled` |
| 谁先成功用谁 | `Promise.any` |
| 竞速并需要取消其余任务 | `Promise.any` + `AbortController` 等取消机制 |

顺序任务在循环里优先 `for...of` + `await`。不要把并发当成默认优化。

## 请求 / 异步状态

在项目已经存在请求状态机时，优先复用它。个人工具生态中优先检查 `@mixte/use`：

- `useRequest` / `useRequestReactive`：优先复用现成的响应、loading、error、finally、事件与竞态处理；
- 不为了单次请求重新实现一套状态机；
- 项目没有这类工具时，再按项目已有 request / composable 模式实现。

## 错误边界

错误处理按“谁能够做出正确决策”分层：

### 底层工具 / 参数校验

发现非法参数、不可能状态时，直接 `throw`。

### 服务 / 封装层

需要更新状态或记录事件时可以 `catch`，完成簿记后继续 `throw`，不要在中间层擅自把错误变成成功结果。

### UI / 入口层

这里才负责最终用户反馈、导航、日志等边界行为。

### 可选数据

确实允许失败的场景才使用空 `catch` 或默认值吞掉异常，并让这个意图明显可读。

## finally 与清理

需要复位 loading、释放资源、恢复临时状态时，优先使用 `finally` / `.finally()`，不要在多个成功 / 失败分支重复写清理逻辑。

## 竞态

对于同一资源的连续执行，如果旧结果可能覆盖新结果，要显式处理竞态。可采用：

- 执行计数 / token；
- AbortController；
- 请求库自带的取消 / 最新请求优先机制。

原则不是固定一种实现，而是：**过期结果不能写回当前状态。**

## 错误类型与文案

- 默认直接使用 `Error`，除非项目已经建立明确的自定义错误层级。
- 内部断言可以使用占位消息，但用户可见文案必须是完整可理解的句子或 i18n key。
- 不要为了“架构完整”引入 Result / Either 或一整套错误码层级，除非项目已经使用它们。
