# JavaScript 写法细节

本文件用于已经确定采用某种 JS 写法后的具体落地。项目 formatter / lint 与邻居实现优先于以下偏好。

## 函数形态

- 具名函数、导出函数和模块内复用 helper 默认写成 `function`。
- 箭头函数用于内联回调、JSX 渲染助手和必须使用表达式的位置。
- 需要动态 `this` 时使用 `function` 表达式。
- 给函数附加方法时，可以使用 `Object.assign(fn, { ... })`；如果项目已有成熟模式，直接复用。

```ts
function clone<T>(value: T) {
  return cloneValue(value);
}

const execute = Object.assign(
  (value: string) => run(value),
  { clear },
);
```

## 参数与调用

- 可选项较多时，用 `options` 聚合；解构时给合理默认值。
- 稳定语义允许同时接受值和取值函数，例如 `boolean | (() => boolean)`；优先复用 `mixte` 已有的判断工具。
- `rest` / `spread` 用于自然的参数透传、批量插入和数组组合，不为了形式统一而滥用。
- 解构用于表达清楚的字段提取、交换或重排；如果解构明显降低可读性，直接使用对象属性。

## 控制流

### Guard clause

优先早返回：

```ts
if (!data?.length)
  return;

if (value == null)
  return defaultValue;
```

避免把主路径埋在多层 `if / else` 中。

### 单语句块

单语句 `if` / `for` 可以省略花括号；多语句块必须使用花括号。最终以项目 formatter / lint 为准。

### 短路与 nullish

- `??` / `?.` 用于自然的缺失值处理。
- `== null` / `!= null` 可以用于同时覆盖 `null` / `undefined` 的场景。
- `condition && doSomething()`、`cache || (cache = create())` 可以用于简单条件执行或惰性初始化。

### 赋值表达式

`if ((value = find(...)))` 这类写法可以使用，但仅在能明显提高紧凑性、且项目 lint 允许时采用；复杂条件不要强行压缩。

## 集合与遍历

| 目标 | 优先选择 |
| --- | --- |
| 转换 | `map` |
| 筛选 | `filter` |
| 查找 | `find` / `findIndex` / `some` / `every` |
| 顺序处理、`await`、`break`、`continue` | `for...of` |
| 需要下标或原地调整 | 经典 `for` |
| 单纯副作用 | `forEach` |
| 真正的聚合 | `reduce` |

`reduce` 不应因为“函数式”而成为普通转换的默认方案。复杂聚合通常优先保证中间状态和累加器易读。

对象转换优先考虑 `Object.entries()` / `Object.fromEntries()`；已经存在成熟工具时不要重复实现。

## Mutation 与复制

- 内部状态允许就地修改：`push`、`splice`、`sort`、`Object.assign` 等都可以直接使用。
- 跨模块边界、缓存快照、需要保留调用方原值时，再考虑复制。
- 浅复制解决结构简单的边界；真正需要深复制时优先使用项目已有的 `mixte.deepClone` 等能力，不自行造轮子。
- 不要为了“不可变”而机械复制每一层对象；先看数据边界和调用关系。

## 表达式复杂度

优先拆成中间变量或命名函数的场景：

- 嵌套三元；
- 一条表达式里出现多个类型断言；
- 很长的 `??` / `?.` 链；
- 复杂 `reduce`；
- 需要读两遍才能理解的短路表达式。

可以保留的紧凑写法：

- 单层三元；
- 简单短路；
- 简单解构默认值；
- 有明确前置保证的单个非空断言。

目标不是“最少字符”，而是**读者一次能看懂主路径**。

## 字符串、数字与基础转换

- 字符串插值优先使用模板字符串。
- 数字转换优先使用 `Number()` 等显式转换，具体项目已有约定优先。
- 正则、URL、固定映射等模块级数据放在顶部常量；命名跟随项目已有风格。
- 日期处理优先使用项目已有库；个人项目默认先检查现有工具，不新增第二套日期方案。

## 注释

- 中文注释解释“为什么”或“一段逻辑正在完成什么”，不要解释显而易见的语法。
- 大段复杂流程可以用空行和块级注释分组。
- 公共 API 的 JSDoc 详度见 `api-design.md`；这里不重复规定具体标签。
